### [n8n](https://github.com/n8n-io/n8n)

> Handle: `n8n`
> URL: [http://localhost:34191](http://localhost:34191)

`n8n` is a low-code workflow automation tool.

#### Starting

```bash
# [Optional] Pre-pull the images
harbor pull n8n

# Start the service
harbor up n8n

# [Optional] Open the web interface
harbor open n8n
```

When running for the first time, `n8n` will require you to set up an owner account. Follow the instructions on the web interface to complete the setup.

Starting `n8n` also starts the n8n Assistant sandbox stack (`n8n-sandbox-certs`, `n8n-sandbox-api`, `n8n-sandbox-runner-1`). Current n8n requires that sandbox during first-time setup. The runner is a privileged Docker-in-Docker container and is not published to the host. Treat it as equivalent to root on the Docker host.

_Optionally_, you might import a sample workflow pre-configured to reach Harbor's built-in Ollama service. Note that it's identical to the [official Ollama example](https://n8n.io/workflows/2384-chat-with-local-llms-using-n8n-and-ollama/) with the only difference being pre-configured Ollama URL.

```bash
harbor run n8n n8n import:workflow --separate --input=/backup/workflows
harbor run n8n n8n import:credentials --separate --input=/backup/credentials
```

#### Usage

You can run arbitrary `n8n` CLI commands with `harbor run n8n`, for example:

```bash
harbor run n8n license:info
harbor run n8n audit
```

Apart from that, you'll be mainly interacting with `n8n` via its Web interface. You can import and export workflows, manage credentials, and more.

- [Official templates for AI workflows](https://n8n.io/workflows/categories/ai/)

#### Credentials configuration

When configuring credentials to access Harbor's services, please ensure to use "Internal" versions of the URLs. For example:
```bash
# "Internal" URL can be obtained with '-i' flag
harbor url -i ollama

# This won't work, as its outside of the Docker network
harbor url ollama
```

#### Configuration

See all configuration options with [`harbor config ls`](./3.-Harbor-CLI-Reference.md#harbor-config-list)

```bash
# All config options
harbor config ls | grep N8N
```

Notably, you can configure the location of the `n8n` workspace.

```bash
# Set the custom workspace location
harbor config set n8n.workspace ~/.n8n
```

Following mount structure (relative to the workspace) is used:
- `/storage` - Persistent storage for workflows and credentials
- `/backup` - Folder to import/export workflows and credentials
- `/shared` - Folder for shared files to be used with File nodes in `n8n`

Sandbox mTLS certificates live in the named Docker volume `n8n-sandbox-tls`, not in the workspace. Regenerate them by removing that volume after `harbor down n8n`.

##### Environment variables

```bash
# Service
HARBOR_N8N_HOST_PORT                  34191
HARBOR_N8N_PG_HOST_PORT               34192
HARBOR_N8N_WORKSPACE                  ./services/n8n
HARBOR_N8N_IMAGE                      n8nio/n8n
HARBOR_N8N_VERSION                    latest

# Postgres
HARBOR_N8N_PG_IMAGE                   postgres
HARBOR_N8N_PG_VERSION                 16-alpine
HARBOR_N8N_PG_USER                    harbor
HARBOR_N8N_PG_PASSWORD                sk-harbor
HARBOR_N8N_PG_DB                      n8n
HARBOR_N8N_ENCRYPTION_KEY             sk-harbor
HARBOR_N8N_JWT_SECRET                 sk-harbor

# Sandbox (n8n Assistant)
HARBOR_N8N_SANDBOX_API_IMAGE          ghcr.io/n8n-io/n8n-sandbox-service-api
HARBOR_N8N_SANDBOX_RUNNER_IMAGE       ghcr.io/n8n-io/n8n-sandbox-service-runner-dind
HARBOR_N8N_SANDBOX_IMAGE              ghcr.io/n8n-io/n8n-sandbox-service-sandbox
HARBOR_N8N_SANDBOX_VERSION            1.2.0
HARBOR_N8N_SANDBOX_SANDBOX_VERSION    latest
HARBOR_N8N_SANDBOX_API_KEY            sk-harbor-n8n-sandbox
HARBOR_N8N_SANDBOX_REGISTRATION_TOKEN sk-harbor-n8n-sandbox-reg
HARBOR_N8N_SANDBOX_RUNNER_KEY         sk-harbor-n8n-sandbox-runner
```

Rotate the three `HARBOR_N8N_SANDBOX_*` secrets together. `HARBOR_N8N_SANDBOX_API_KEY` is both the key n8n uses (`N8N_SANDBOX_SERVICE_API_KEY`) and the key the sandbox API accepts (`SANDBOX_API_KEYS`).

##### n8n Assistant

The sandbox stack is enough for first-time setup. n8n Assistant itself stays off until you add a model API key (Anthropic, OpenAI, OpenRouter, or an OpenAI-compatible endpoint) in the instance AI settings, or via:

```bash
harbor env n8n N8N_INSTANCE_AI_MODEL_API_KEY sk-...
harbor restart n8n
```

When SearXNG is also running, Harbor points n8n Assistant web search at it:

```bash
harbor up n8n searxng
```

##### Webhook URL

`n8n` often requires configuring `N8N_WEBHOOK_URL` environment variable for external access. Below is an example that'll work when it runs within Harbor's Docker network:

```bash
# Set the webhook URL
harbor env n8n N8N_WEBHOOK_URL http://localhost:$(harbor config get n8n.host.port)
```
