### [AutoGPT Platform](https://github.com/Significant-Gravitas/AutoGPT)

> Handle: `autogpt`
> URL: http://localhost:34061

[![Discord Follow](https://dcbadge.vercel.app/api/server/autogpt?style=flat)](https://discord.gg/autogpt) &ensp;
[![Twitter Follow](https://img.shields.io/twitter/follow/Auto_GPT?style=social)](https://twitter.com/Auto_GPT)

Harbor runs the current all-in-one AutoGPT Platform container: web app, APIs,
workers, PostgreSQL, RabbitMQ, Valkey, and FalkorDB. The first startup can take
several minutes and the Platform itself needs approximately 5–6 GiB of memory,
in addition to any local model server.

> [!IMPORTANT]
> `AUTOGPT_PUBLIC_URL` must be the exact origin used in the browser, including
> scheme and port. When the setting is empty, Harbor derives
> `http://localhost:34061` for a direct start or the standard HTTPS hostname for
> the Traefik combination. Before using a LAN hostname, IP address, reverse
> proxy, tunnel, or non-default Traefik HTTPS port, set the exact origin
> explicitly:
>
> ```bash
> harbor config set autogpt.public.url "http://192.168.1.50:34061"
> ```
>
> The Harbor Traefik combination sets its matching HTTPS origin automatically
> when Traefik uses port 443.

#### Choose a model provider

AutoGPT does not need every provider key. Choose one of these paths.

##### OpenRouter (simplest remote setup)

One OpenRouter key provides AutoPilot chat and unified-search embeddings:

```bash
harbor config set openrouter.key "sk-or-v1-..."
harbor up autogpt
```

Graphiti memory also uses an OpenAI embedding model in remote mode. Add one
OpenAI key if you want Graphiti's semantic memory rather than chat alone:

```bash
harbor config set openai.key "sk-..."
harbor up autogpt
```

Harbor passes these shared keys into AutoGPT without copying them into the
AutoGPT service file. An AutoGPT-specific value set with `harbor env autogpt`
takes precedence.

##### Ollama on the same Harbor host

Start AutoGPT together with Ollama:

```bash
harbor up autogpt ollama
```

The combination automatically:

- routes AutoPilot chat and Graphiti through Ollama's OpenAI-compatible API;
- pulls `qwen3.5:4b` for generation and `nomic-embed-text:latest` for Graphiti;
- requests a 32,768-token Ollama context window; and
- waits for both model-pull attempts before AutoGPT starts.

If a pull fails because a model name or network request is invalid, AutoGPT
still starts; inspect `harbor logs ollama-init` before troubleshooting missing
models in AutoGPT.

Change the models or context before starting if needed:

```bash
harbor config set autogpt.ollama.model "qwen3.5:4b"
harbor config set autogpt.ollama.embedding.model "nomic-embed-text:latest"
harbor config set autogpt.ollama.context.length 32768
```

The Ollama process is shared, so the 32K context setting also applies to other
services using that Ollama container while this combination is running.
Starting the combination after changing that setting may recreate the shared
Ollama container and briefly interrupt those services. CPU inference works but
can be slow; model RAM/VRAM is additional to AutoGPT's approximately 5–6 GiB
requirement.

> [!NOTE]
> `nomic-embed-text` emits 768-dimensional vectors. It works for Graphiti, but
> AutoGPT's unified-search database requires exactly 1,536 dimensions. Harbor
> deliberately does not set `STORE_EMBEDDING_MODEL` to nomic. On a fresh
> Ollama-only installation, AutoGPT therefore cannot populate its global search
> index: results across blocks, documentation, library agents, workspace files,
> and chat sessions may be incomplete or empty. Marketplace listing search
> retains its own direct text fallback. AutoGPT's background indexer logs a
> non-fatal `text-embedding-3-small` model-not-found warning at startup and on
> periodic retries. A fresh backfill can emit many such non-fatal warnings and
> an error summary without making the container unhealthy. Complete global
> search requires a gateway on `CHAT_BASE_URL` that routes embedding requests
> to a verified 1,536-dimensional backend (or injects a 1,536-dimension request
> for a compatible model).

##### Another OpenAI-compatible endpoint

For a remote inference server or a model server elsewhere on your LAN, set one
complete local/custom transport tuple:

```bash
harbor env autogpt CHAT_USE_LOCAL true
harbor env autogpt CHAT_BASE_URL "http://host.docker.internal:11434/v1"
harbor env autogpt CHAT_API_KEY "local"
harbor env autogpt CHAT_FAST_STANDARD_MODEL "qwen3.5:4b"
harbor env autogpt GRAPHITI_LLM_MODEL "qwen3.5:4b"
harbor env autogpt GRAPHITI_RERANKER_MODEL "qwen3.5:4b"
harbor env autogpt GRAPHITI_EMBEDDER_MODEL "nomic-embed-text"
harbor up autogpt
```

`CHAT_BASE_URL` must be reachable from inside the AutoGPT container and must
expose both the generation model and the embedding model on the same
OpenAI-compatible endpoint. Harbor maps `host.docker.internal` to the Docker
host gateway, including on native Linux Docker and Unraid. A single-model
llama.cpp server is therefore not enough by itself: use llama.cpp's
multi-model/router setup or put a compatible router in front of separate
generation and embedding servers. The endpoint must expose the configured
Graphiti embedding model. Unified semantic search separately requires an
embedding route or model that returns exactly 1,536 dimensions. If its model
name differs from `text-embedding-3-small`, set `STORE_EMBEDDING_MODEL` to that
name only after verifying the returned vector length. Without that
1,536-dimensional route, Graphiti can still use its own embedding model, but
fresh global search results may be incomplete or empty; marketplace listing
search retains a direct text fallback.

#### First account and registration

New-account registration starts enabled so a fresh installation is usable.
Anyone who can reach the page can register while it remains enabled.

1. Open the configured URL and create the intended first account.
2. Promote that account from the host:

   ```bash
   harbor exec autogpt autogpt-admin promote you@example.com
   ```

3. Close registration and recreate the service:

   ```bash
   harbor config set autogpt.allow.new.accounts false
   harbor up autogpt
   ```

To allow only specific email addresses during setup, provide a comma-separated
allowlist before starting:

```bash
harbor config set autogpt.signup.allowlist "you@example.com,other@example.com"
```

#### Starting and operating

```bash
# Optional: pre-pull the image
harbor pull autogpt

# Start with the configured remote/custom provider
harbor up autogpt

# Open the web app
harbor open autogpt
```

For Traefik, configure Harbor's domain as usual. When
`autogpt.public.url` is unset, the combination automatically sets AutoGPT's
public URL to `https://autogpt.<domain>`:

```bash
harbor config set traefik.domain "example.com"
harbor up autogpt traefik
```

If Traefik publishes HTTPS on a non-default port, set the browser-exact AutoGPT
origin too:

```bash
harbor config set traefik.https.host.port 8443
harbor config set autogpt.public.url "https://autogpt.example.com:8443"
harbor up autogpt traefik
```

The current upstream image and floating release tag are the defaults. Pin or
replace them through Harbor configuration when needed:

```bash
harbor config set autogpt.image "significantgravitas/autogpt"
harbor config set autogpt.version "latest"
```

Advanced AutoGPT-only settings live in `services/autogpt/override.env` and can
be managed without editing the file directly:

```bash
harbor env autogpt VARIABLE value
```

#### Upgrading from Harbor's legacy Auto-GPT service

This is a fresh AutoGPT Platform installation, not an in-place upgrade of
Auto-GPT Classic. Platform state is stored in a Docker-managed `autogpt-data`
volume so PostgreSQL can apply the required Unix permissions on Linux, macOS,
and Windows hosts. Harbor leaves the old `services/autogpt/data`, `workspace`,
and `logs` directories untouched, but the new container does not mount or
migrate them.

The Docker-managed volume survives an ordinary `harbor down`, but it is not
inside the Harbor folder and is therefore not captured by a backup of that
folder alone. Back up the volume separately, and do not use volume-removal or
Docker volume-pruning operations if you need to retain Platform state. Harbor
also does not delete the old Classic image or directories; expect both old and
new image data to remain until an administrator deliberately cleans up the
unused legacy artifacts.
