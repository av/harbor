### [Perplexica](https://github.com/ItzCrazyKns/Vane)

> Handle: `perplexica`
> URL: [http://localhost:34041/](http://localhost:34041/)

Perplexica is an AI-powered search engine (project evolved to Vane by the original author). It is an open source alternative to Perplexity AI. Harbor runs community-maintained images for this service.

#### Starting

```bash
# [Optional] Pull the perplexica images
# ahead of starting the service
harbor pull perplexica

# Start with local model and search backends
harbor up perplexica ollama searxng

# [Optional] Open the service in browser
harbor open perplexica
```

#### Configuration

Harbor will pre-connect Perplexica to `searxng` and `ollama` services, if running together. You can also provide API keys for the LLM APIs supported by the Perplexica.

The frontend and backend use separate host ports. If you open Perplexica from another device on your LAN, set the public host to the hostname or IP that device uses (without a scheme or port) before starting the service:

```bash
harbor config set perplexica.public_host harborai.lan
harbor up perplexica ollama searxng
```

`HARBOR_PERPLEXICA_PUBLIC_HOST` defaults to `localhost`, for browsers on the Harbor host. The setting changes both the browser's HTTP API and WebSocket addresses to use `HARBOR_PERPLEXICA_BACKEND_HOST_PORT` (default `34042`); the browser must be able to reach that port as well as the frontend port (`34041`). Ollama and SearXNG use their Docker-network addresses internally and need no LAN address setting.

```bash
# [Optional] Set the API keys for supported backends

# OpenAI, via keys pool
harbor openai keys add <your key>
# OpenAI, via Harbor config as a main key
harbor config set openai.key <your key>

# Groq, via Harbor config
harbor config set groq.key <your key>

# Anthropic, via Harbor config
harbor config set anthropic.key <your key>
```

Harbor bind-mounts `services/perplexica/source.config.toml` into the container as Perplexica's base `config.toml` — it carries the config schema, while backend endpoints and keys are injected via environment variables from the cross-service configs. Apart from that, you may use `services/perplexica/override.env` in the Harbor workspace for additional local configuration overrides. Unfortunately, some of the settings (Embeddings config) can't be pre-configured so have to be done via the Perplexica UI.

The backend runs as the host user with an init sidecar pre-creating `./services/perplexica/data`, so the SQLite history database stays owned by your host user.
The same sidecar prepares `./services/perplexica/cache` for the local embedding model cache; it survives restarts without writing into the image's read-only `node_modules` tree.
