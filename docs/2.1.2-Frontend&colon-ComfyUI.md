This ui will let you design and execute advanced stable diffusion pipelines using a graph/nodes/flowchart based interface.

Harbor runs ComfyUI via the actively maintained [yanwk/comfyui-boot](https://github.com/YanWenKun/ComfyUI-Docker) image (previously: the unmaintained `ghcr.io/ai-dock/comfyui`; see [Migrating from ai-dock](#migrating-from-ai-dock) below if you used ComfyUI in Harbor before this switch).

> [!NOTE]
> On first start, Harbor provisions the Flux.1-schnell model set (~25GB) used by the Open WebUI integration. This can take a long time depending on your connection — monitor progress with `docker logs harbor.comfyui`. Set `harbor config set comfyui.provisioning false` to skip.

#### Starting

```bash
# [Optional] Pre-pull the comfyui image
# otherwise will be pulled on start
harbor pull comfyui

# Start the service; the first start downloads models,
# which takes a long time
harbor up comfyui

# See service logs
harbor logs comfyui -n 100

# [Optional] once started, open the UI
# in your default browser
harbor open comfyui
```

- When running with other inference backends - ensure that you have VRAM available for the models. Unlike `ollama`, `comfyui` won't try to offload if there's not enough VRAM. You can check the VRAM usage with [`harbor top`](./3.-Harbor-CLI-Reference.md#harbor-top)
- Harbor ships a basic Flux workflow (`harbor-flux`) that appears in the ComfyUI workflow browser — it matches the Open WebUI image-generation integration

#### Image variants and GPU support

The image tag is selected per accelerator:

- **NVIDIA**: the default `HARBOR_COMFYUI_VERSION` tag (`cu130-slim-v2`, CUDA 13.0). GPU passthrough via `compose.x.comfyui.nvidia.yml` or the CDI-generated overlay.
- **AMD**: `compose.x.comfyui.rocm.yml` is applied automatically when Harbor detects `/dev/kfd`. It mounts `/dev/kfd` + `/dev/dri` and switches the tag to `HARBOR_COMFYUI_ROCM_VERSION` (default `rocm7` — ROCm 7 PyTorch with support for recent GPUs including Strix Halo / gfx1151).
- **CPU**: `harbor comfyui version cpu` for the dedicated CPU image, or keep any variant and add `harbor config set comfyui.args '--cpu'`.

See all available tags in the [upstream README](https://github.com/YanWenKun/ComfyUI-Docker).

#### Workspace

Everything ComfyUI touches — the ComfyUI checkout itself, models, custom nodes, outputs, user settings — is persisted in a single host-owned workspace, bind-mounted at `/root` in the container:

```bash
# Default: ./services/comfyui/root, configurable:
harbor config get comfyui.workspace

# Open the workspace / generated outputs in the file manager
harbor comfyui workspace open
harbor comfyui output

# Wipe the workspace (models included); it is re-initialised on next start
harbor comfyui workspace clear
```

Because ComfyUI itself lives in the workspace (`<workspace>/ComfyUI`), updates done via ComfyUI Manager persist across restarts — no sync step is needed (the old `harbor comfyui workspace sync` is deprecated and a no-op).

An init sidecar (`comfyui-init`) chowns the workspace to your host user before the main container starts so it stays manageable without `sudo`.

#### Provisioning

On every start, Harbor's `services/comfyui/provisioning.sh` runs as the image's `pre-start.sh` hook. When `HARBOR_COMFYUI_PROVISIONING=true` (default) it idempotently downloads the Flux.1-schnell diffusion model, its text encoders and VAE, and a few ESRGAN upscalers into `<workspace>/ComfyUI/models/{diffusion_models,clip,vae,upscale_models}`. Downloads authenticate with `HARBOR_HF_TOKEN` / `HARBOR_CIVITAI_TOKEN` when set.

```bash
# Disable model provisioning entirely
harbor config set comfyui.provisioning false
```

#### Authentication

Upstream ComfyUI has **no built-in authentication** (the old ai-dock image added its own; `harbor comfyui user/password/auth` are deprecated no-ops). Don't expose the port directly to untrusted networks — use `harbor tunnel comfyui` for ad-hoc sharing, or front it with `traefik` and an auth middleware.

#### Integrations

- `webui` (Open WebUI) — mounts `config.comfyui.json` registering ComfyUI as the `image_generation` engine at the internal URL `http://comfyui:34031`, with a Flux.1-schnell workflow matching the provisioned models. This powers "Image Generation" inside WebUI chats.
- `traefik` — `compose.x.traefik.comfyui.yml` exposes the UI at `https://comfyui.${HARBOR_TRAEFIK_DOMAIN}`.

ComfyUI listens on `HARBOR_COMFYUI_HOST_PORT` inside the container as well (Harbor passes `--port` via `CLI_ARGS`), so internal consumers and the host use the same port number.

#### Configuration

Following options are available via [`harbor config`](./3.-Harbor-CLI-Reference.md#harbor-config):

```bash
# The port of the ComfyUI's web interface,
# used both on the host and inside the compose network
HARBOR_COMFYUI_HOST_PORT       34031

# Docker image repository and tag
HARBOR_COMFYUI_IMAGE           yanwk/comfyui-boot
HARBOR_COMFYUI_VERSION         cu130-slim-v2

# Tag used by the auto-applied ROCm overlay
HARBOR_COMFYUI_ROCM_VERSION    rocm7

# Location of the workspace folder (ComfyUI checkout, models,
# custom nodes, outputs). Relative to $(harbor home) or absolute.
HARBOR_COMFYUI_WORKSPACE       ./services/comfyui/root

# Additional CLI arguments for ComfyUI (e.g. --cpu)
HARBOR_COMFYUI_ARGS

# Enable/disable the Flux model provisioning on start
HARBOR_COMFYUI_PROVISIONING    true
```

```bash
# Shortcuts
harbor comfyui version [tag]
harbor comfyui image [repo]
```

#### Migrating from ai-dock

Harbor previously ran ComfyUI via `ghcr.io/ai-dock/comfyui`, which is unmaintained upstream (frozen at ComfyUI v0.2.2, ROCm 6.0). The switch to `yanwk/comfyui-boot` changes:

- **Workspace**: new default `./services/comfyui/root` (mounted at `/root`). Your old ai-dock workspace at `./services/comfyui/workspace` is left untouched. To carry models over, copy them from `workspace/storage/stable_diffusion/models/*` into `root/ComfyUI/models/*` (note: `unet` is now `diffusion_models`).
- **Auth**: ai-dock's `WEB_USER`/`WEB_PASSWORD` login is gone — upstream ComfyUI has no auth.
- **Ports**: the ai-dock management portal (34032) and Syncthing UI (34033) no longer exist; only the ComfyUI port remains.
- **Rollback**: `harbor comfyui image ghcr.io/ai-dock/comfyui`, `harbor comfyui version latest-cuda` (or `latest-rocm`), `harbor config set comfyui.workspace ./services/comfyui/workspace` — then restore the removed env keys via `harbor env comfyui` if you need auth. Note the old compose wiring (portal ports, provisioning URL) is no longer present, so full rollback is best done by checking out a pre-migration Harbor version.
