### [Rapid-MLX](https://github.com/raullenchai/Rapid-MLX)

> Handle: `rapidmlx`<br/>
> URL: [http://localhost:34991](http://localhost:34991)

Rapid-MLX is an open-source local LLM inference server for Apple Silicon built on MLX. Harbor runs the installed server on the macOS host and exposes its OpenAI-compatible API to containers through a Caddy proxy.

#### Starting

Install Rapid-MLX on the host first:

```bash
brew install rapid-mlx
harbor up rapidmlx
harbor up webui rapidmlx
```

With `rapidmlx.manage.host=true`, Harbor runs `rapid-mlx serve` with the configured `rapidmlx.hf.path` and explicit `rapidmlx.runner.port`. Models use the standard Hugging Face cache, honoring `HF_HOME` and `HF_HUB_CACHE`. No model files or Python environment are stored in the service directory. First startup can take longer than Harbor's 60-second readiness wait while a model downloads; inspect the host log and retry once the server is ready.

Use it with host tools:

```bash
harbor launch --backend rapidmlx --model mlx-community/Qwen3.5-4B-MLX-4bit codex
```

To use a server you already run yourself:

```bash
rapid-mlx serve qwen3.5-4b-4bit --port 8000
harbor config set rapidmlx.manage.host false
harbor up webui rapidmlx
```

The native OpenAI base URL is `http://localhost:8000/v1`. Without an explicit port, Rapid-MLX selects the first free port in 8000–8009. Harbor supplies an explicit port so the proxy endpoint remains predictable. If port 8000 is occupied, update both settings:

```bash
harbor config set rapidmlx.runner.port 8001
harbor config set rapidmlx.upstream.url http://host.docker.internal:8001
```

#### Configuration

Defaults live in `services/rapidmlx/default.env`. Set options with [`harbor config`](./3.-Harbor-CLI-Reference.md#harbor-config):

| Variable | Default | Purpose |
|---|---|---|
| `HARBOR_RAPIDMLX_HOST_PORT` | `34991` | Harbor proxy port |
| `HARBOR_RAPIDMLX_IMAGE` | `caddy` | Proxy image |
| `HARBOR_RAPIDMLX_VERSION` | `2-alpine` | Proxy version |
| `HARBOR_RAPIDMLX_WORKSPACE` | `./services/rapidmlx` | Host logs and managed process PID |
| `HARBOR_RAPIDMLX_UPSTREAM_URL` | `http://host.docker.internal:8000` | Native endpoint reachable from containers |
| `HARBOR_RAPIDMLX_RUNNER_PORT` | `8000` | Explicit native server port |
| `HARBOR_RAPIDMLX_MODEL` | `mlx-community/Qwen3.5-4B-MLX-4bit` | Model ID for launch and consumers |
| `HARBOR_RAPIDMLX_HF_PATH` | `mlx-community/Qwen3.5-4B-MLX-4bit` | Model repository for host startup and pull |
| `HARBOR_RAPIDMLX_API_KEY` | `not-needed` | Key for host startup, model discovery, launch, and environment-based integrations |
| `HARBOR_RAPIDMLX_MANAGE_HOST` | `true` | Start the installed host runner automatically |
| `HARBOR_RAPIDMLX_VOLUMES` | empty | Extra proxy volume mounts |
| `HARBOR_BIFROST_RAPIDMLX_BASE_URL` | `http://rapidmlx:8080` | Bifrost provider endpoint |
| `HARBOR_BIFROST_RAPIDMLX_API_KEY` | `not-needed` | Bifrost provider key |
| `HARBOR_BIFROST_RAPIDMLX_MODELS` | `*` | Bifrost model selection |

Rapid-MLX requires no key by default; `not-needed` is a placeholder. The default placeholder leaves authentication disabled on a managed server. Harbor passes any other configured key to a managed host runner through `RAPID_MLX_API_KEY`. For an authenticated external server, match its key in Harbor and in the consumer. SillyTavern requires its key to be set in its UI. Aider and Chat UI use static `not-needed` placeholders in their config fragments; override those fragments when authentication is enabled. Bifrost has a separate key setting.

##### Volumes

The proxy mounts only `services/rapidmlx/Caddyfile`. Host logs and the managed PID file live in `services/rapidmlx/logs/`, which is ignored by Git. `harbor down rapidmlx` and `harbor rapidmlx stop` stop only a host process started by Harbor; externally managed processes are left running.

#### Model Management

```bash
harbor models ls --source rapidmlx
harbor models pull --source rapidmlx mlx-community/Qwen3.5-4B-MLX-4bit
harbor models rapidmlx pull mlx-community/Qwen3.5-4B-MLX-4bit
harbor rapidmlx ls
```

Pull delegates to Harbor's existing Hugging Face download command and shared cache. `harbor models rm --source rapidmlx` is unsupported; manage the shared cache manually. Set `rapidmlx.hf.path` to change the served model and `rapidmlx.model` to its advertised `/v1/models` ID for consumers, then restart the managed server.

#### API

- Host proxy base URL: `http://localhost:34991/v1`
- Container base URL: `http://rapidmlx:8080/v1`
- Native server base URL: `http://localhost:8000/v1`

Rapid-MLX provides `/v1/chat/completions`, `/v1/responses`, `/v1/models`, and `/v1/embeddings` when an embedding model is served. Anthropic Messages is available at `/v1/messages`, using a base URL without `/v1`.

#### Integrations

Like oMLX, Rapid-MLX has consumer overlays for `webui`, `chatui`, `aider`, `boost`, `litellm`, `bifrost`, `optillm`, `opint`, `astrbot`, `cognee`, `mindsdb`, `mi`, `ml-intern`, `npcsh`, `open-design`, `opennotebook`, `openterminal`, `anythingllm`, `cmdh`, `hermes`, `plandex`, `sillytavern`, and `traefik` when enabled. These provide the same configuration hooks as the existing backend integrations; some consumers still require model selection in their UI.

#### Troubleshooting

```bash
harbor rapidmlx status
harbor rapidmlx logs
curl http://localhost:8000/v1/models
```

Ensure the `rapid-mlx` executable is on Harbor's PATH. Metal inference runs on the Apple Silicon host; the Linux container only proxies requests. For a server on another host, disable host management and set `rapidmlx.upstream.url` to an address reachable from containers. The proxy's `/health` route checks the proxy itself; use `/v1/models` to check the inference server.
