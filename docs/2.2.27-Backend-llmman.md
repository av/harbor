### [llmman](https://github.com/llmmanorg/llmman)

> Handle: `llmman`<br/>
> URL: [http://localhost:35080](http://localhost:35080)

llmman is a local model runner that serves the Ollama API (alongside OpenAI- and Anthropic-compatible ones) on port 17434. Models are pulled as OCI artifacts from any registry (Docker Hub, GHCR, quay) or straight from Hugging Face (`hf.co/org/model`), and are served by upstream `llama.cpp` (`llama-server`), `vllm`, or `mlx-lm`.

Like [Docker Model Runner](./2.2.22-Backend-Docker-Model-Runner.md), [MLX](./2.2.23-Backend-MLX.md) and [oMLX](./2.2.24-Backend-oMLX.md), llmman runs natively on the host. Harbor exposes it to containers through a Caddy proxy; Harbor does not install or start llmman for you.

#### Starting

Install and start llmman on the host:

```bash
curl -fsSL https://raw.githubusercontent.com/llmmanorg/llmman/main/install.sh | sh
llmman serve
llmman pull gemma4
```

Then bring up the Harbor proxy, optionally together with a frontend:

```bash
harbor up llmman
harbor up webui llmman
```

Open WebUI is configured to talk to llmman over its Ollama-compatible API, so models pulled with `llmman pull` appear in the model selector.

#### Configuration

##### Environment Variables

Following options can be set via [`harbor config`](./3.-Harbor-CLI-Reference.md#harbor-config):

```bash
# Harbor proxy port
HARBOR_LLMMAN_HOST_PORT            35080

# Proxy image
HARBOR_LLMMAN_IMAGE                caddy
HARBOR_LLMMAN_VERSION              2-alpine

# Where the host llmman server listens (LLMMAN_HOST on the host side)
HARBOR_LLMMAN_UPSTREAM_URL         http://host.docker.internal:17434

# URL other Harbor containers use to reach llmman
HARBOR_LLMMAN_INTERNAL_URL         http://llmman:8080
```

If you start llmman on a different address, e.g. `LLMMAN_HOST=0.0.0.0:18000 llmman serve`, update the upstream accordingly:

```bash
harbor config set llmman.upstream.url http://host.docker.internal:18000
```

##### Volumes

The Harbor `llmman` service only mounts `services/llmman/Caddyfile` into the proxy container. Models live in llmman's own store on the host.

#### API

Harbor exposes llmman at `http://localhost:35080`; containers use `http://llmman:8080`. Both serve:

- Ollama API: `/api/generate`, `/api/chat`, `/api/embed`, `/api/tags`, `/api/show`, `/api/ps`, `/api/pull`, `/api/push`, `/api/copy`, `/api/create`, `/api/delete`, `/api/version`
- OpenAI-compatible: `/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`, `/v1/models`, `/v1/responses`
- Anthropic-compatible: `/v1/messages`

No API key is required; if a client insists on one, any placeholder works.

#### Troubleshooting

```bash
harbor logs llmman
```

The proxy healthcheck only verifies that Caddy is up. If requests return `502`, make sure `llmman serve` is running on the host and reachable at `HARBOR_LLMMAN_UPSTREAM_URL`:

```bash
curl http://localhost:17434/api/version
```
